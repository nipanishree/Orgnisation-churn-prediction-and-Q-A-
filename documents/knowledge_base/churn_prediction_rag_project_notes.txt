TotalCharges Handling
---------------------
TotalCharges should be converted to a numeric type:

df["TotalCharges"] = pd.to_numeric(
    df["TotalCharges"],
    errors="coerce"
)

The 11 resulting missing TotalCharges values correspond to customers with
tenure = 0.

These rows should not automatically be deleted during EDA. Their treatment
should be decided during preprocessing.

Important EDA Interpretation Rule
----------------------------------
The above values are observed relationships/correlations in the dataset.
They should not be interpreted as proof of causation.

For example, a high churn rate for electronic check does not prove that
changing the payment method will cause churn to decrease.

EDA Segmentation
----------------
Create tenure groups for analysis:

df["tenure_group"] = pd.cut(
    df["tenure"],
    bins=[0, 12, 24, 36, 48, 60, 72],
    labels=[
        "0-12",
        "13-24",
        "25-36",
        "37-48",
        "49-60",
        "61-72"
    ],
    include_lowest=True
)

Calculate churn rate by tenure group:

tenure_churn_rate = (
    pd.crosstab(
        df["tenure_group"],
        df["Churn"],
        normalize="index"
    )["Yes"] * 100
).round(2)

Monthly charge groups can also be created for EDA:

df["monthly_charge_group"] = pd.cut(
    df["MonthlyCharges"],
    bins=[0, 30, 60, 90, 120],
    labels=[
        "0-30",
        "31-60",
        "61-90",
        "91-120"
    ],
    include_lowest=True
)

RAG System
----------
The project also includes a Retrieval-Augmented Generation system.

Goal:
Allow users to upload multiple documents and ask questions related to those
documents.

Expected RAG flow:

Documents
   |
   v
Document Upload
   |
   v
Document Parsing
   |
   v
Text Cleaning
   |
   v
Chunking
   |
   v
Embedding Model
   |
   v
Vector Database
   |
   v
Similarity Search
   |
   v
Relevant Chunks
   |
   v
LLM
   |
   v
Grounded Answer + Sources

Important RAG requirements:
- Support multiple uploaded documents.
- Store document chunks and embeddings in a vector database.
- Retrieve relevant chunks for user queries.
- Restrict answers to retrieved/contextual information.
- Reduce hallucination by using grounding and source references.
- Maintain document-level/user-level security.
- Prevent one user's documents from being exposed to another user.
- Validate uploaded files.
- Avoid storing secrets in source code.
- Log useful metadata without exposing sensitive document content.

RAG Security
------------
Security should include:
- Authentication/authorization where applicable.

- Isolated document namespaces or metadata filters.
- Secure environment variables.

- File type and size validation.
- Safe temporary file handling.
- No secrets committed to Git.
